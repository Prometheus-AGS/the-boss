# C14.2 distinct Drain and control visibility operation

This procedure is authored for the completed packaged delivery boundary. Authoring it does not establish an operation result. Root freezes source and builds the actual package before running the maintained launcher.

Use Node.js with the actual checkout, maintained package launcher and unique receipt output directory:

```text
node scripts/operate-uar-lifecycle-controls.mjs --boss <absolute-checkout> --launcher <absolute-maintained-launcher.mjs> --output <absolute-receipt-directory>
```

The launcher must export the existing `launchBoss` procedure. This bounded launcher currently supports the actual macOS package only. Supply the same established `BOSS_C142_GATEWAY_ENDPOINT`, `BOSS_C142_GATEWAY_ALIAS`, `BOSS_C142_GATEWAY_PROVIDER_ID`, `BOSS_C142_GATEWAY_MODEL_ID` and `BOSS_C142_GATEWAY_CREDENTIAL_ENV` inputs as the preceding operations; the named credential variable must contain the real protected gateway credential. An optional `BOSS_CADENCE_SURREAL_BINARY` identifies the actual pinned SurrealDB 3.3.0 executable. No credential value is copied into receipts. Experimental profile flags are refused.

The procedure uses the isolated application profile supplied by the maintained launcher and registers a disposable user workspace. Existing trusted IPC installs the fixed starter team binding only to configure an advertised gateway provider; it submits no team task. It explicitly selects that provider as the isolated runtime default, installs the fixed starter agent binding, creates one on_demand durable instance and activates it. It opens the selected runtime's durable panel, compares visible actions to advertised capabilities, and clicks the actual Drain button. Acceptance requires a retained completed Drain command and dormant lifecycle while the managed UAR PID, start timestamp, port, generation and selected service identity remain unchanged. No inference turn is submitted; this proves Drain on an active idle instance, not draining an in-flight model call.

The existing native host helper starts a second actual external local UAR with real SurrealDB memory storage and explicit durability attestation false. While Work remains selected on the managed runtime, its administration detail route must show the existing accessible refusal/banner and recovery navigation, omit the durable panel, and leave native managed state unchanged. After intentionally selecting the external profile, the loaded panel must report instances unsupported and hide all six durable actions. No unsupported mutation or externally owned process restart is invoked. The managed selection is restored and only the helper's owned subprocesses are stopped. This exercises local ownership and native durability eligibility; it does not claim remote federation coverage.

`operation.json` records Boss/UAR source identities, source diff, local pin and payload manifest/marker hashes, actual app ASAR/native/SurrealDB binary hashes, the maintained launcher and each transitive scenario helper hash. `evidence.json` records actual command/state/process/control observations and structured failures. HTTP failures retain method, endpoint path, status and safe native code when provided by the existing main adapter. Arbitrary native/IPC response bodies and messages are not serialized. Missing native transport detail is left absent. A visible Drain error can supply the same safe method/status/code diagnostics without storing its raw alert text. Cleanup failure prevents success.

The checked-in first approval lifecycle receipt and corrective cancellation receipt are preserved by exact hashes, original source references and their recorded passing checks. They are not rerun or relabeled as evidence at this new source boundary. The first receipt's failed cancellation clause remains failed; cancellation/Stop credit belongs to the separate corrective receipt. This increment does not certify the whole parent C14.2, installed Windows acceptance, remote federation, or new approval/cancel/detach behavior.
