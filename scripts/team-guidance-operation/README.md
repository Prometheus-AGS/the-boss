# Completed packaged team-guidance operation

Root owns execution at the completed delivery boundary. This procedure is source
preparation until the real application operation has produced a successful
receipt. It uses the existing maintained isolated packaged launcher; no fake
runtime, registry seed or approval bypass is introduced.

```text
node scripts/operate-team-guidance.mjs --boss <checkout> --launcher <maintained-boss-launch.mjs> --output <new-receipt-directory>
```

The existing `BOSS_C15_GATEWAY_*` credential-reference/configured-model contract
is required by the production setup path. Credential values stay in memory and
are never written to the operation report. Model recommendation is an actual
packaged creator `selectModel` result for the operator-declared configured alias;
prices and tier deliberately remain unknown. Discovery/authoring does not prove
new inference.

The scenario opens real settings, reads all eight preset descriptions, authors a
product-research team with explicit models and a reviewed skill, imports actual
creator `guide` output, explicitly maps implementer/reviewer proposals, imports
and accepts the exact configured model recommendation, saves an immutable
revision and deploys it. Renderer reload reopens the original revisions with
their guidance/model source and resource selections. Finally the visible
single-agent alternative must open ordinary Work. No team run or external effect
is requested by this authoring increment.

Source/artifact hashes, safe identity references and outcomes are recorded.
Native Windows operation, process restart, measured cost comparison and regulated
certification are not asserted. Root records the applicable outstanding phase
acceptance separately.
