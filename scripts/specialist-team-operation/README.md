# Packaged specialist-team operation

Run only at root's completed next-increment boundary:

```text
node scripts/operate-specialist-team-authoring.mjs --boss <completed-checkout> --launcher <maintained-boss-launch.mjs> --output <new-receipt-directory>
```

This uses the existing reusable-team operation launcher and `BOSS_C15_GATEWAY_*`
environment contract in its `io.mjs`. It requires an actual packaged Mac app,
matching UAR source/payload pins and the normal qualified execution profile.
Gateway credentials stay in memory and private configuration; receipts record
safe source identities, hashes, model receipts and bounded approval evidence.

The visible Settings editor creates the coordinator plus six specialists,
selects the configured gateway model manually, edits project scope, output and
evidence text, and saves four immutable revisions. Each new member field is
changed separately while other member/resource choices and earlier revisions
remain intact. The operation deploys the final revision, runs all specialists
against only the disposable README through real UAR, then reloads and reopens
saved authoring fields and the pinned run without repeating inference.

Approval handling uses the existing trust validator with the explicit seven-role
preset. It permits only the existing bounded native delegation/messages and the
prepared README read; directory listings are denied. Scope text grants no
authority. It does not install skills, alter model metadata or qualify profiles.

Source preparation is not execution evidence. Root owns execution after the
complete production/build boundary and independent review. Renderer reload is
not process restart. Native Windows acceptance and requested model-policy
compliance remain pending/unknown respectively.
