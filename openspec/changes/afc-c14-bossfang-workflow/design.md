# Packaged workflow operation

The existing maintained Boss launcher creates the isolated packaged application profile. Reuse the existing real gateway/workspace setup and the main-process BossFang connection/grant lifecycle. The main process retains credentials; dashboard evaluation reads its incumbent guest session and performs authenticated native reads without exporting the token. Work selection and the managed UAR PID/start/port are captured before admission and compared after each workflow and cleanup. Stop only the managed BossFang process created in that profile; leave external resources and the selected UAR alive.

The operation enters the actual embedded dashboard workflow page. Native workflow creation uses the existing catalog schema; visible run, approval and cancellation actions must reach the actual native routes. Read the corresponding native workflow-run and delegation projection, retain original workflow/run/step/admission/definition/binding/UAR identifiers, and compare them to the dashboard. Export output hashes/counts and public event/control identities rather than model text, raw tool arguments, credentials or response/log bodies.

Each requested filesystem effect is constrained to the operation's disposable registered workspace and one exact marker file. Approval is allowed only after its real pending call identifies that file/content and original admission. Denial and cancellation must settle on their original delegated tasks and leave their respective files absent; no re-admission, fallback executor or invented approval decision is permitted. The ordinary bound agent and tool resources are admitted through the accepted private host-context contract. The scoped BossFang grant never substitutes the host launch credential. Missing or incompatible context, capability or prepared effect is reported as a refused prerequisite; the procedure cannot bypass it.

Root supplies the newly built native BossFang source and immutable platform record, updates the existing payload pins, compiles the dashboard into the actual native binary, freezes all production sources, and packages once. The procedure checks the expected source, packaged binary digest, compiled workflow asset manifest, local UAR source/marker and actual ASAR/binary hashes before launching. No implementation-time builds, tests, lint, reviews or operations occur here.

The accepted host-effect increment adds only an opaque context reference to the existing ordinary bound target. The Boss registers private filesystem MCP/tool-admission resources with UAR through its host authority and sends a safe `delegatedHostContexts` inventory with the existing protected Connect handoff. The native applied connection owns that inventory; the dashboard uses its existing status query and selects only one exact workspace/binding/immutable-definition match. Existing authored references and admitted runs remain fixed when inventory or grants change. `delegatedHostContextId` becomes `delegated_host_context_id` in the existing full-run body. UAR validates the original context lease, grant, runtime epoch and binding, and calls the private host decision callback before resolving its existing approval waiter.

The scoped native edit set is `crates/librefang-types/src/uar_run.rs` (safe inventory/target DTO), `crates/librefang-llm-drivers/src/drivers/uar.rs` and new `uar_delegated_host_context.rs` (existing applied connection inventory), `crates/librefang-llm-drivers/src/drivers/uar_run/{mod,wire}.rs` (opaque wire/capability), `crates/librefang-api/src/routes/uar_supervisor.rs` and `uar_delegation/connections.rs` (existing protected Connect/refresh DTO and status), and `crates/librefang-api/src/routes/workflows/uar_dispatch.rs` (existing bound target flattening). Dashboard edits are `src/api.ts`, `src/lib/uarWorkflowTarget.ts`, `src/components/UarWorkflowStepTarget.tsx` and its existing five locale catalogs under `crates/librefang-api/dashboard/`. No native executor variant, scheduler, secret persistence, new resource server or payload pin changes belong to this edit set.

The operation extension uses the real owning native approval projection and typed `bossfang.delegated_approval.inspect` host inspection for exact prepared-effect path/content hashes. Three disposable files cover one approved effect, denial without effect, and cancellation while approval remains pending. No raw private resources, tool arguments or model output are written to receipts. This design describes source work; runtime acceptance remains pending until root freezes, packages and operates all production collaborators.
