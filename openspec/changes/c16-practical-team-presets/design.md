# Design

## Source contract

The existing flow remains Settings draft → strict shared IPC schema → private immutable revisions → bundled creator compiler → private workspace binding → normal Work execution. Add template IDs `product-research`, `marketing-brand`, `logo-design`, `mobile-design`, `customer-feedback`; each has coordinator, two bounded contributors and a separate reviewer. Keep existing coding/product-design/specialist-delivery templates unchanged.

Presets fill responsibility, instructions, output instructions and evidence instructions. Project scope starts empty for the operator to specify. New members receive existing readonly filesystem options; coordinator delegates without filesystem tools. Model, skills and knowledge start unselected. Reviewed skill catalog/source pins and manual overrides remain authoritative; no preset auto-installs or silently binds a skill. Requirements and evidence are attributed task data, not authority. The compiler already includes populated delivery fields in source identity and compiled instructions, so no new runtime contract or persistence is needed.

Customer-feedback produces a feedback summary and issue drafts in returned artifacts. Instructions require identifying repository/connector/action permissions needed for future issue creation and explicitly prohibit sends, issue creation or publication without separate authorization. Logo/design produces a design specification and asset-production handoff; image rendering is not falsely claimed. Mobile uses the declared platform and records unresolved SDK/device checks.

## UI contract

Refine the incumbent Operate settings surface (variance 3, motion 2, density 7). Reuse labeled Buttons and SettingDescription with semantic tokens, wrapping and existing disabled/dirty/save/deploy behavior. Show a localized preset description for the selected draft and shared guidance that resources require explicit selection. No raw JSON or new navigation. Preserve all member editor fields and controls. New button labels and descriptions are translated in thirteen existing locales.

## Operation boundary

One source-only driver reuses the existing maintained launcher, setup, UI and readonly approval helpers. It creates/saves all five presets; representative product research, marketing/brand and logo/design runs must use real normal-profile member attempts, exact manually selected model, an explicitly selected reviewed readonly skill, prepared README reads and correlated artifacts. Revise a delivery field, retaining prior immutable identity and all resource choices. Reload and reopen saved drafts and pinned runs without repeated inference. Record source identities, safe hashes and credential-free receipts. Renderer reload is not process restart; native Windows acceptance remains pending.

Only root executes after the whole delivery and package finish. No unit/lint/compiler/check/build/install/test/review loops here. The operation must deny writes/external effects and record connector requirements, never manufacture effects.

## Instruction reconciliation

The explicit approved implementation assignment supersedes openspec-propose's generic planning pause and repository DCO instruction: commits are signed with Assisted-by only. Node 24.11.1 is present; versions.toml is absent in this worktree, so canonical mini pins were read without modification. Compass freshness metadata is absent; bounded source search identifies template/adapter/editor callers, and runtime evidence remains root-owned. UI routing uses prometheus-ui-ux, prometheus-impeccable-core, ui-ux-pro-max, better-writing and cherry-electron-dev guidance. The latter's per-edit loop is superseded by the completed-delivery boundary.
