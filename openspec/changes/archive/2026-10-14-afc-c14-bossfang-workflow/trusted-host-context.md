# Trusted delegated workspace effects

This approved C14.4 implementation extends the [ordinary workflow design](design.md) to resolve its observed host-admission blocker. The Boss main process owns the private delegated MCP/admission bridge, selected managed grant registration and bounded protected approval inspection. UAR owns the host-authenticated context registry and canonical waiter; BossFang owns safe applied context choices and ordinary workflow projection. Existing schedulers, Apps, Teams and Work selection retain their authority.

Settings → Connect resolves the actual selected runtime and registered workspace, reads its existing deployment-binding catalog, and registers supported bound-agent contexts through host-only `POST /api/uar/full-harness/v1/delegated-host-contexts`. The context captures exact grant/workspace/runtime epoch, immutable definition and binding, canonical workspace directory, request-owned MCP resources and private paired-host admission. Only safe identity/expiry choices enter protected native connection configuration. The renderer receives no launch token, scoped bearer, callback URL, headers or raw tool arguments through this change.

Each new grant creates new contexts; no implicit renewal or migration changes an admitted run. Original bridges remain retained for original runs. Expiry, revocation, generation change or identity mismatch refuses protected effects. Terminal cleanup releases the original context and bridge.

The existing authenticated private bridge accepts UAR's exact delegated-approval callback. It verifies the original host-readable task, context, run, authoritative pending issuer/challenge/admission/tool-call/event and canonical history before recording the human decision with the existing authority provider. UAR then revalidates its pending waiter before resolution. Protected IPC `bossfang.delegated_approval.inspect` accepts only an owning BossFang task identity and returns exact safe context/pending identities and existing prepared-effect hashes/path after the same ownership checks.

The desktop renderer boundary is the existing `IpcApiService.handleRequest` → `validateSender` gate: embedded webviews cannot invoke this inspection route. Main reads the authenticated owning `/api/uar/delegations/{bossTaskId}` projection, resolves only a privately retained original context, then reads the original host-authenticated task and approval. Callers cannot supply a URL, workspace, context, runtime or admission identity. The private bridge retains its existing loopback/Host/Origin and bearer checks; the callback cannot reach the renderer. Public inspection failures reuse the translated retained-authentication message without response bodies or private callback addresses.

Inspection reports the actual UAR history and `durable` flag. A clean owning cancellation at an unclaimed pending effect records `cancelled` with no human decision; teardown or channel loss can instead record `interrupted`. The operation must observe the actual settlement. `pending.cursor` remains nullable as in the native pending DTO. These reads are sequential observations, not an atomic snapshot. Inspection is available while the original private context remains retained; it does not recreate expired authority after application restart.

Acceptance remains the root-owned packaged ordinary workflow: one bounded approved filesystem effect and a second run cancelled at its actual approval boundary, with unchanged Work runtime. No implementation-time tests, lints, compiler runs, builds, reviews or operations occur here; source completion is not runtime acceptance.
