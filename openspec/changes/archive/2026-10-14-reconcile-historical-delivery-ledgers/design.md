# Design

## Context

The canonical phase is complete at revision 705 while its enclosing run still says running. Separate markers retain code 61/61 tasks and 20/20 changes, versus qualification 43/61 terminal (42 passed, one skipped duplicate). Older Boss lists contain 87 unchecked boxes across eighteen changes; initiative lists retain exactly eighteen unqualified tasks.

## Goals / Non-Goals

Reconcile retained evidence at its original scope and revision. Do not infer native Windows acceptance, new-candidate acceptance, full harness compatibility or broader representation/federation qualification from source completion or a later package.

## Decisions

Use disjoint evidence owners for product and initiative OpenSpec roots. Preserve each original predicate; source-complete alone cannot satisfy a mixed operation task. Missing evidence remains pending. Archive via OpenSpec with explicit main-spec synchronization; retain original history and document superseded prescriptions instead of fabricating their execution.

Use typed KBD decisions and independent completion records. The installed CLI has no run-complete command: retire the already administratively closed enclosing run through its supported cancellation command if no complete-run surface exists, naming administrative retirement rather than product failure. Keep the phase complete and qualification partial; do not create a successor run. Never hand-edit generated waypoint, position or progress files.

## Risks / Trade-offs

Older task lists combine implementation and qualification; preserve unproved requirements even when that prevents archiving a whole change. Generated run status can differ from phase status; the receipt and current prose must explain both rather than claim full certification.

## Migration Plan

Record pre-reconciliation hashes and canonical counts, retain archived files, apply supported commands, then compare task identities and final counts. Rollback is the preserved Git history and append-only journal; do not rewrite events. One completed documentation/evidence consistency review is sufficient. No builds or passing product operations run.
