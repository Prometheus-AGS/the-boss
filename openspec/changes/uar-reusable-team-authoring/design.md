# Design

The Boss main process owns authoring and installation. Renderer forms submit typed intent over the existing Prometheus IPC boundary. A versioned authoring record lives in application-owned durable state; it contains no credentials. Editing creates a new immutable package version and leaves earlier package and run references intact.

The package compiler reuses the existing `document` canonical digest, `starterPackage` agent shape and UAR `PackageManifest`/`TeamDefinition` draft.2 contracts. A guided preset supplies bounded coordinator/member responsibilities. The operator may name the team, edit shared and member instructions, choose per-role advertised models, and select discovered skills with explicit per-role scope. The portable package expresses aliases and requested resources; model IDs, credential refs, workspace paths, skill installations and grants remain in a private deployment binding. Tool selection cannot broaden host approval policy.

Deployment uses the current UAR capabilities, package preflight/install, and binding preflight/CAS/install endpoints. Preflight errors are surfaced intact. Work's existing definition and binding selector discovers the result through the normal snapshot. The UI provides a direct route from team administration to Work. The real packaged operation script drives the application entrypoint and records exact installed package/run digests; it is not a mock-only acceptance substitute.

Security boundary: authoring text and selected skills are untrusted data; only the existing trusted host and UAR binding/approval boundary may activate tools or credentials. Editing does not change an active run's pinned definition or silently rebind an installed workspace.

The host-workspace extension follows the pinned draft.2 common extension contract: `{required: true, value: {version: 1, ...}}`. Portable member tools/servers and private binding workspace/tools/servers live inside `value`; main-process host admission validates the strict envelope and its payload. This repairs the canonical shape mismatch observed as HTTP 422 at the predecessor's real package boundary. Stored immutable revisions remain unchanged; an author must explicitly save a new revision to compile corrected bytes. Promotion also requires the coordinated native host reader repair and the stable predecessor coding producer repair.

## C15.1 reviewed model policy bridge

The existing member editor imports the operator-reviewed JSON output of the merged agent-team-creator `models-select` command. Task-guided role selection remains the existing `guide`/`guidance.mjs` contract; team → role → ordered skills → task policy and deterministic strength/capability/known-price selection remain `models.mjs` under agent-team-models. The Boss adds no recommender, wizard, policy evaluator, dependency, runtime HTTP endpoint or service.

The supported result carries concrete `selected.id` (gateway wire alias), nullable `selected.provider` and `selected.catalogId`, effective policy, applied layers, rejected candidates, explanation, warnings, diagnostics, catalog provenance and freshness. Unknown capability/price/catalog-identity metadata remains unchanged in the result. A result without a selected concrete wire alias cannot be applied through this bridge. The existing selector may select an unmapped configured alias only when every declared policy constraint permits its unknown metadata. Import preserves the original JSON bytes and source SHA-256 plus a deterministic structured-result SHA-256 in the private authored record. This is an operator-reviewed artifact, not independently certified recommendation provenance.

Typed IPC `prometheus.uar.teams.review_model_policy` accepts the source JSON, reuses the bundled skill's credential-field/environment-value check, excludes application-secret values, and requires the selected alias to be advertised by the currently configured liter-llm gateway. Import freezes its exact enabled provider/model target separately in private `bindingTarget` provenance and compares every non-null reviewed identity; it never fills unknown raw catalog identity. The editor displays the recommendation and rationale as pending until the operator chooses Use recommendation or explicitly uses the existing manual dropdown. `modelPolicyMode` records reviewed versus manual choice; the recommendation remains inspectable in either mode. Import alone does not mutate the selected model, configure credentials, deploy or infer.

Save validates the result/source digest identity. The existing immutable source compiler includes recommendation/source digests, choice mode, exact selected model and any newly captured binding target in member `sourceIdentity.digest`; the portable definition still carries its existing role alias and no recommendation payload, credentials, endpoint or catalog document. A policy-only or choice-mode revision therefore changes immutable package identity while preserving earlier records and runs. Deployment requires an explicit choice and, for an accepted recommendation, checks the separately frozen provider/model target at the existing `configureTeamModel` boundary. Older fully mapped receipts without the new field retain their original shape and use their reviewed target; no older source or package is rewritten. Manual choices use that boundary normally; they do not silently rewrite or reselect the reviewed policy. Reimport a reviewed result after intentionally changing task/skill policy; the editor never claims an old selection was reevaluated.

A-3 boundary hardening is limited to untrusted recommendation JSON crossing privileged IPC and persistence, and to the exact configured gateway-alias binding. Literal credential fields and known environment/application secrets are rejected using the existing skill protection plus the application credential store; this is not a general secret scanner. Native credentials remain outside portable definitions in the existing protected store.

The focused real-operation entrypoint is `node scripts/operate-reusable-team-model-policy.mjs --boss <source-root> --launcher <maintained-packaged-launcher.mjs> --output <receipt-directory> --selection <reviewed-models-select-result.json>`, with the established `BOSS_C15_GATEWAY_*` configured identity and credential environment reference. It reuses the existing packaged launcher, ordinary configuration/workspace APIs, editor/Work controls and approval operator, and runs only the new `model-policy-scenario.mjs`. It imports and accepts the result, retains a deliberate manual choice in an immutable revision, reaccepts, saves/deploys/runs the exact model, compares effective receipts, and reloads the renderer to inspect retained policy/older revision identity. It does not repeat the accepted seven-assertion procedure, use a fake model, seed registry metadata or bypass approval. Creation task is C15.1. This new increment has no executed compiler, lint, test, build, reviewer or operation evidence; the lead owns the complete build and packaged operation boundary.

## C15.1 reviewed creator role guidance — source only

The existing editor accepts the merged creator `guide` result through typed IPC `prometheus.uar.teams.review_guidance` with `{source: string}`. The shared receipt is `{schemaVersion: 1, source: 'agent-team-creator/guide', sourceJson, sourceDigest, digest, result}`. `sourceJson` retains the original bytes as UTF-8 text; `sourceDigest` hashes that text and `digest` hashes the complete parsed result. Known proposal fields identify roles for preview, while JSON extension fields, questions, reasons, missing inputs, skill suggestions, ownership, dependencies, inputs/outputs and requested model policies remain inspectable. Main reuses the existing bundled creator team validator and artifact credential protection; save reparses the source and verifies both identities. This is an imported operator-reviewed result, not proof of independent approval or policy compliance.

Import attaches the receipt to the private draft without changing members. A ready result can be applied only after the operator selects explicit `{sourceRole, memberRole}` mappings to existing non-coordinator members; selections begin unchecked. Apply copies a proposal's description to responsibility and prompt to instructions, preserves member order, exact configured model, tools, skills and knowledge, and records manual model choice. It does not save, deploy, install suggested skills, grant filesystem paths or translate role dependencies into native graph edges. The root-supplied coding proposal maps implementer to worker and reviewer to reviewer, preserving the Coding preset coordinator. Existing model acceptance/override, skill catalog, pricing/accounting, authority and graph checks remain the established paths. Requested medium/hard policies remain visible planning metadata; the configured GPT6.1Sol alias remains unclassified while the human tier question is unanswered.

Optional `reviewedGuidance` and `guidanceMappings` persist in the existing versioned private authoring record. Guidance/source digests and mapping identities join the existing member source digest only when guidance is present, so earlier records and their compiled identity remain unchanged. The raw guide, policy metadata and credentials do not enter portable native definitions. Member edits stay available; role renaming/removal updates its explicit mapping, and saving produces a new immutable revision. All thirteen renderer locale catalogs translate the import, preview, apply and planning/manual-policy notices. The existing controls expose stable guidance receipt/mapping and per-tool attributes for the separate packaged operation writer.
