# Design

Use the existing neutral Operate surface, shared Button/Textarea/Input controls,
semantic tokens and normal tab order. The novice sequence remains visible;
secondary role/cost/regulated decisions use progressive disclosure. The ordinary
Work link remains an explicit action; it does not create an agent or change the
selected team. All existing presets receive their own localized explanation.

The actual creator guide already supplies alternatives and skillDiscovery.
Expose those fields in the shared Zod contract as optional, retaining complete
source JSON and catchall compatibility. Existing review/import/save/compiler
paths preserve provenance. Role resources are readable but retain the original
JSON detail view; they do not become automatically installed or granted skills.

Reviewed policy displays nullable known prices and class. Preserve original
pricing/provenance/freshness, do not infer currency or zero prices. Budget limits,
planning classes and measured usage remain separate. Combining sequential roles
is instructions-driven and retains output ownership; independent review remains
separate. Regulated guidance is an operator checklist, not certification.

The boundary driver operates actual packaged creator modules and visible
authoring controls. It saves/deploys the changed guide/model policy, reloads and
reopens unchanged revisions, and follows single-agent Work. The new capability is
authoring guidance; repeating prior inference is not required for its acceptance.
Native Windows, real cost comparison and broad regulated qualification remain
separate. Root owns build, operation, acceptance and ledgers.

Instruction reconciliation: operator task forbids interim lint, compiler, test,
review or build runs and forbids Signed-off-by; those explicit restrictions
override stale repository prose. Commits use Assisted-by. Compass freshness
metadata and matching worktree graph are unavailable; bounded source tracing
identifies existing component/schema/route and persistence flows. UI context uses
prometheus-ui-ux, its project protocol, incumbent DESIGN/.impeccable, the portable
Impeccable adaptation, better-writing and relevant React guidance. No native UI
engine, screen review or certification is claimed during source preparation.
