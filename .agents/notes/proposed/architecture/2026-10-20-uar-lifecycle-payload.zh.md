# Agent Note: UAR 生命周期载荷绑定

Status: proposed

English | Chinese counterpart: 2026-10-20-uar-lifecycle-payload.md

## 问题

生命周期启动器需要匹配的 UAR 二进制文件。如果打包时复制旧的构建目标文件，
载荷仍可能被标记为较新的源码版本。Windows 启动器还需要可取消的继承输入，
并等待子进程实际退出的确认。

## 提案

将操作者已批准的跨仓库生命周期实现保留在草稿中，直到验证得到授权。
将显式本地原生候选版本固定到 UAR 提交
`6d50cb8a05fb2af33e0928dc8d7ac3ff0c5f3e46`。要求生产脚本使用已提交的 Git 对象
和全新的目标目录，并核对源码及树、平台、功能、协议、可执行文件、构建日志、
归档和文件清单的身份。现有公共载荷保留原有发布身份。旧的本地模式仍要求
干净的工作区；显式候选模式使用已提交的 Git 对象，排除无关的未提交文件。

Windows 使用继承的重叠 stdin，保留子进程句柄，关联私有生命周期响应，并等待
子进程实际关闭。发送信号或经过一段时间不能证明进程已终止。本提案记录已批准的
源码设计，不是已完成的验收记录，也不能代替 GitHub 上的 Spec 审批。
草稿链接到 UAR OpenSpec 和操作者决策。

## 考虑过的替代方案

- 重新标记现有目标可执行文件：即使文件哈希内部一致，源码来源仍然不真实，因此拒绝。
- 使用公共载荷进行本地验收：该载荷不包含本次尚未验收的生命周期源码，因此拒绝。
- 显式候选模式要求共享工作区完全干净：不可变 Git 对象导出已经排除无关修改，因此拒绝。

## 验收标准

- AC1 — 打包的本地 sidecar 与固定的已提交源码及所需生命周期协议一致，过期或不一致的记录被拒绝 (verification: packaged artifact).
- AC2 — EOF 关闭和显式重新连接收到关联的生命周期结果，完成前观察到所拥有的子进程退出 (verification: Electron).
- AC3 — Windows 继承输入的取消通过实际重叠 I/O 和子进程回收完成，不使用固定的成功期限 (verification: packaged artifact).

## 风险

验证保持关闭。尚未执行候选构建、打包、进程场景、类型检查或审查。这些本地记录
证明完整性，但不能提供针对恶意载荷所有者的签名编译器证明。公共客户构建和
Windows 证据仍是独立关卡。只有真正获得授权的证据覆盖全部标准后，提案才可
转为已实现；草稿不得暗示已经就绪。
