# Agent Note: UAR 启动选择与使用凭据绑定身份的 BossFang 连接

Status: implemented

[English](2026-11-09-uar-startup-owner.md) | 中文

## 问题

启动时绑定所有者的外部 UAR 可能声明支持宿主指定身份，但会拒绝与凭据绑定身份不同的所有者，导致 BossFang 配置收到 HTTP 403。首选端口被占用或摄取目录不可写也会影响托管运行时启动。

## 决策

通过只读能力接口检查已验证外部实例的身份模式。仅在收到明确的身份不匹配响应时使用凭据绑定的所有者。凭据保留在主进程中，实例变更会使进行中的检查失效。启动时提供已识别的本地 UAR 或托管运行时选项，摄取目录在托管运行时重启后生效。

## 考虑过的替代方案

在写入请求中更换身份可能重复执行操作。将通用认证响应视为发现结果可能误识别其他监听服务。

## 后果

切换运行时后，已有任务保留原运行时和授权。隐藏发现信息的外部运行时需要使用受保护的凭据手动注册。

## 验证

- Regression — `pnpm build:mac:arm64` 和[打包版 Mac 验证场景](../../../../openspec/changes/uar-bossfang-compass-startup/macos-evidence.md)：验证摄取目录、端口回退、BossFang 认证启动、重启、会话恢复与运行时切换。
