# Selected method and recovery references

VLBV is the verification method for every phase. `.kbd-orchestrator/project.json` carries `verificationMethod` (written as `"VLBV"` by `kbd-init`); when it is absent the pack default is VLBV. No per-phase decision is needed, and a project file cannot deviate: any other `verificationMethod` value is reported as a blocker. To **deviate** for one phase, record a signed decision whose summary begins with `KBD-METHOD ` followed by JSON containing `phaseId`, the currently bound `contractDigest`, `method`, `cadence` (when generated code executes under that method), `reason`, `retiredMethods` and `references` (`path` plus exact SHA-256). A deviation without `cadence` and `reason` is `BLOCKED`, and `scripts/kbd-phase-close-eval.mjs` names the deviation in the closure packet. Record it only from explicit operator selection through `prometheus kbd decision record`; replace it using the existing `--supersedes` lineage. Do not infer a deviation from a filename, old command, memory or available tool.

The governing instructions checked for conflicts are the files the active harness actually loads, taken from that harness's profile in `config/harnesses/capabilities.json` (`profiles.<harness>.rulesFiles`; pass `--harness <id>` or set `PROMETHEUS_HARNESS`; `PROMETHEUS_HARNESS_PROFILES` names another profiles file). A first-match host such as Zed can be shadowed by an earlier file (`.rules`, `.cursorrules`, …), and Codex `AGENTS.override.md` replaces `AGENTS.md`; both are reported under `effectiveRules.shadowing`. Without a profile (file absent, harness unnamed or unknown) the historical file set is read and that is reported under `effectiveRules.profile`. Policy is read from a marked block — `<!-- kbd-policy:begin -->` … `<!-- kbd-policy:end -->` with lines such as `compiler-exception: retired` and `cadence-exception: none` — and free-text matching is only the fallback for files that predate the block. The pack's own managed context region is never scanned.

`node <pack-root>/scripts/kbd-method-context.mjs --project <root> --phase <id> [--harness <id>] --write` reads canonical status/disposition and produces `method-context.json`/`method-context.md` beside the phase contract. These are derived readable indexes, never an authority ledger. `--json` prints structured discovery; `--require-resolved` returns exit 2 for `BLOCKED` (missing or ambiguous references, or canonical status unavailable) and `CONFLICT` (unacknowledged policy conflict). Status precedence is `BLOCKED > CONFLICT > RESOLVED_REFERENCES`. The helper never executes generated-code verification, installs dependencies, edits the contract, selects a method, retries an effect or changes canonical state.

The `prometheus` CLI is optional. Without it the helper still produces an index from project files, but the phase binding, any deviation and the latest supersession are reported unresolved (`BLOCKED`), never guessed. Absence is reported once on stderr, not treated as a failure of the session.

Init/Assess discover host governing instructions/capabilities and current method. Spec/Plan carry acceptance-bearing calibration references under the contract identity. Execute, child/harness handoff, pause/resume and compaction recover the current index and re-resolve canonical decisions before dependent action. Carry its path through role inputs, selected source/evidence provenance and handoff read order and start prompt (`kbd-handoff` and `agent-team-creator` handoffs already do); these fields grant no execution authority.

Define acceptance/scenarios before generation. Finish the complete agreed value-phase production before any generated-code tests, builds, imports, lint, typecheck, hooks or probes; editor/LSP diagnostics read during generation are static reading, not execution. Generated code executes only at B4 (the boundary packet, once) and B5 (an authorized repair) — `references/boundaries.md`. Scenario definition is distinct from executable test authoring. A task/hour/commit/reviewer request, compiler problem or renamed slice never creates a boundary. Surface conflicting host/skill wording; do not silently rewrite operator-owned instructions. A host compiler or hourly-cadence exception is reported as a policy conflict; it is never VLBV permission during generation.

The index retains included value/exclusions, contract/binding and plan revision, stage operations, retired-method lineage and the current decision's `supersedes` link, candidate/evidence freshness, adopted budgets with effective ceilings and consumption high-water, open receipt/blocker obligations and preservation requirements. Reconcile unknown effects before retry; never reset consumption or discard original failures. Resolve latest authorized supersession, not just the hash of an old pointer. Changing acceptance-bearing reference content requires the existing contract amendment authority where applicable.

Describe control as instruction-only, observed, enforced within a named existing boundary, or unsupported. File hashing observes identity, not model obedience. Only actual runtime commands enforce their named mutations. This integration provides no generic shell fence, universal tool interception, release authority or automatic successor. Windows execution is not claimed from Node compatibility alone; the helper is plain Node ESM with no shell, Python or symlink dependency.

## Policy conflict acknowledgement

Before dependent work, show each conflict's path, current SHA-256 and issue. An explicit operator resolution is recorded through the existing signed decision writer:

```text
prometheus kbd --path <project-root> decision record --command-id <unique-id> --id <decision-id> --summary 'KBD-POLICY-ACK {"phaseId":"<canonical-phase-id>","path":"<policy-path>","sha256":"<current-file-sha256>","issue":"<exact-reported-issue>","note":"<operator resolution and its provenance>"}'
```

Exactly one current, non-superseded acknowledgement must match phase, path, hash and issue, with a nonempty resolution note. Conflicts expose `acknowledged` and `ackDecisionId`. Changed files, retired acknowledgements and ambiguous acknowledgements do not clear the conflict. Existing acknowledgements match the reworded conflict issue only after they are re-recorded; a file carrying the policy block without an exception no longer conflicts. Replace an acknowledgement using `--supersedes`; retain its history. Acknowledgement records a resolution, never permission to violate governing host policy. In particular, the complete value-phase boundary still applies. Without the `prometheus` CLI no acknowledgement can be read, so a detected conflict stays unacknowledged (the index is `BLOCKED` in that case anyway).

This uses the same instruction-level trust model as a `KBD-METHOD` deviation: canonical decisions carry signed journal provenance, but their summary does not establish a new actor authorization boundary. Do not describe this as universal host enforcement.

## Selected-method recovery and authority

Before dependent work, run `node <pack-root>/scripts/kbd-method-context.mjs --project <project-root> --phase <canonical-phase-id> --write` (or read the phase-local `method-context.md` when Node is unavailable) and act on its `status`:

- `RESOLVED_REFERENCES` — continue with the recovered method, contract and stage authority; preserve the same references in role inputs, dispatch and handoff read order.
- `BLOCKED` — the contract, its binding, a calibration reference, a supersession or a deviation's cadence/reason is missing or changed, or canonical status is unavailable; resolve it explicitly. Prior commands, memory and tool inventories are not fresh authority.
- `CONFLICT` — a governing rule file the active harness loads grants an exception VLBV forbids (for example a compiler check or an hourly integration gate during generation). Stop before dependent work and show the conflict; continue only after the operator records a `KBD-POLICY-ACK` decision for that file's current hash. Never rewrite operator-owned policy, and never treat an exception as authority for tests, builds, dry-runs or generated-code verification.

VLBV is the method for every phase (project default `verificationMethod: "VLBV"`); a deviation exists only as a signed `KBD-METHOD` decision naming the method, its execution cadence and its reason, and it is disclosed in the closure packet. Define acceptance before generation; generated code executes only at the value-phase boundary (B4) and, after an authorized repair, at B5 — see `kbd-process-orchestrator/references/boundaries.md`. Tasks, hours, commits, reviewer requests and compiler problems create no boundary. Preserve original evidence, consumed budgets and unresolved effects across resume and supersession; reconcile an uncertain effect before any retry. Full rules: `kbd-process-orchestrator/references/method-context.md`.
