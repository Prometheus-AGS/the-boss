# Frozen application source reconciliation

`candidate reconcile-frozen` binds a completed real feature operation to an already built, launched and frozen application when separately operated `scripts/` drivers required a correction. It appends evidence under the existing run lock and command-ID journal. It does not rebuild, dispatch a feature, change original source refs or attempts, reset clocks, qualify platforms, publish or award delivery credit. A product repair requires a new build and candidate; reconciliation cannot attribute an old application to repaired product source.

The input schema is [frozen-source-reconciliation.schema.json](../schemas/frozen-source-reconciliation.schema.json). Supply `candidateId`, `authorityRef`, `reason`, `applicationRepository`, `operationEvidencePath`, `provenancePath`, `operationDriverCommit`, `driverPaths`, `buildCheckpointId`, `launchCheckpointId`, and exactly two `artifacts`: the original DMG and `app.asar`. The single-source, single-driver input still accepts `driverPath` without `applicationRepository`. Multiple source refs require an explicit application repository. Original top-level and nested refs remain intact; preserved tracked patches and untracked bytes reconstruct each original fingerprint recursively, including dirty snapshots. A missing, changed or mismatched snapshot is refused.

The operation evidence must be an actual completed operation, with ordered `startedAt`/`finishedAt`, `sourceRefs.boss` equal to the frozen application revision, `sourceRefs.appAsarSha256`, and `operationDriverSources: [{path, sha256}]` containing exactly one match for each declared absolute driver path. Keep the observed whole-checkout dirty diff in `sourceRefs.bossDiffSha256`. Separately record `operationDriverDiffSha256`: SHA256 of the raw bytes from `git diff --binary <frozen-application-revision> <operation-driver-proof-commit> -- <driverPaths sorted>`. Do not replace the whole-checkout digest with this narrower digest. Legacy single-driver evidence without generated outputs may use its original `bossDiffSha256` for the driver diff.

Each declared driver must have changed, its proof commit must descend from the frozen application commit, and its committed bytes must match both actual operation evidence and the current driver file. The frozen builder must exclude `scripts/`. Other application tracked and untracked source must still equal the original preserved source, except the individually proven generated skill outputs below. Original nested application pins and fingerprints must remain unchanged. Other named repositories retain their frozen snapshots, and their later checkout state is recorded separately. A subsequent checkout advance is refused at adoption/finish until reconciled.

`provenance.applicationBuildSource` identifies the frozen application revision. When supplied, `provenance.candidateSourceRefs` must match the entire original source array. `provenance.artifacts` maps repository-relative DMG and ASAR paths to `{sha256,size}`. Their actual bytes must match; successful source-bound build and launch checkpoints must precede the operation.

For the observed mini packaging outputs, the provenance may include `generatedOutputDeclaration`:

```json
{
  "source": { "repository": "<frozen application>/resources/prometheus-skills-mini", "revision": "<frozen nested mini revision>" },
  "transform": "mini-pack-skill-text-v1",
  "producerSources": [
    { "path": "scripts/before-pack.js", "sha256": "<SHA256 of frozen Git blob>" },
    { "path": "scripts/package-prometheus.js", "sha256": "<SHA256 of frozen Git blob>" }
  ],
  "paths": [
    { "path": "resources/skills/delivery-cadence/SKILL.md", "sha256": "<actual generated byte SHA256>", "size": 123 }
  ]
}
```

Use actual evidence for every listed output. This is a declaration format, not an operation receipt. Do not mutate provenance already adopted or referenced by an immutable receipt; author a new provenance file.

Both producer hashes must match frozen application Git blobs. The frozen builder must call `scripts/before-pack.js`, that producer must invoke `package-prometheus`, and the packager must contain the supported mini skill transform and copy destination. Each output maps exactly from `resources/skills/<skill>/<file>` to frozen mini `skills/<skill>/<file>`. Non-Markdown bytes remain identical. Markdown preserves `node scripts/<helper>.mjs` when that skill-local helper exists in the frozen mini tree; otherwise it renders `boss-mini <helper>.mjs`. This is the observed `renderPackSkillText` transform, not a general generator runner. Unsupported producer behavior is refused.

Each declared output must match the reproduced source bytes, its current `resources/skills` bytes, and the packaged file adjacent to the actual ASAR at `app.asar.unpacked/resources/prometheus-skills-mini/skills/...`. That packaged mini's `release-manifest.json` must identify the same frozen mini revision and exact file hash. The reconciliation retains hashes of the packaged files and manifest, and finish checks them again. A directory wildcard, generic ignored `resources/` tree, changed mini pin, or unrelated output has no exemption.

The returned `operatedSource.dirtyDiffSha256` is the driver-only diff digest; `wholeCheckoutDirtyDiffSha256` retains the separate observed checkout digest. `driverSources` is sorted by relative driver path. For one driver, `driverSha256` remains its byte SHA256; for multiple drivers it is SHA256 of `JSON.stringify(driverSources)` using the returned array and object-key order (`path`, then `sha256`). A feature receipt copies this returned `operatedSource`, the returned operation evidence hash, and the original candidate source refs. Original operation timestamps remain distinct from reconciliation `recordedAt`.

The final functional exercise must use completed actual feature proof. Preparing this contract or checking hashes does not supply feature, installed acceptance, publication or delivery evidence.
