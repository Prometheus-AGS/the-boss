# Pipeline contract v3

One active delivery owns canonical KBD state; one separately authorized scope can work ahead in isolated source/output roots after production freeze. Work-ahead is assignment, not a second scheduler or phase owner. Its firstWorkAt survives promotion; existing child phases remain on the parent's continuous clock.

The CLI starts state v3 runs and reads historical versions. Explicit migrate requires oldMutatorsStopped:true, backups journal/state/hooks/reports, retains history, and preserves candidate-specific publication debt. Old writers reject v3. Native platform acceptance and remote consumer capability remain separate evidence.

Long checkpoint, hook, learning and publisher effects run outside the run mutex. Claims identify run/candidate/attempt/token; durable receipts merge only after reloading state. Unknown effects require reconciliation. Owned resource paths coordinate cooperating sessions through ~/.prometheus/cadence/resources-v1, not arbitrary remote workflows.

The operation contract records outcome, promisedCapability, procedure, checkpointId, production entrypoint or approved creationTaskRef, target.kind, evidenceLevel, expectedResult, prerequisites, isolatedResources, externalEffects, authorityRefs and limitations. At ready the source procedure exists and matches its checkpoint. Build-produced paths become required after build. An approved creation task may fill its entrypoint through ready; changing the capability or effects requires scopeAuthority and scopeReason.

Candidate freeze requires outputRoots (or checkpoint outputRoots) and actual source refs. Ready freezes implicitly; candidate freeze is also available. Dirty bytes and initialized submodules are preserved; uninitialized submodules retain pins with explicit unobserved checkout state. Candidate identities and immutable attempts survive repairs.

Publication modes manual/count/interval/either preserve every as a count alias. Explicit tick or normal commands evaluate UTC opportunities; no daemon wakes. Each due candidate keeps its own obligation until platform, metadata and website receipts match. Installed acceptance remains separate. A declared consumer must supply source, correlation, artifact, serialization, predecessor and website capability evidence before dispatch.

See profile.md for CLI requests, adapters.md for KBD boundaries and hooks.md for trusted handler registration.

Interrupted short commands retain their command ID and unknown outcome. Resume accepts commandRecovery:{commandId,evidencePath} only with a matching run/command, inspectedRevision from current status, not-applied outcome, authorityRef, reason and effectChecks [{absent:true,evidence:...}]. This is an explicit owner attestation after inspection, not an automatic claim that an external effect was absent. Repeated failed commands return their recorded error; known successful commands return their receipt.
